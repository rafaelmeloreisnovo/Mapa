# OECG V1 continuous improvement

Continuous improvement is represented as repeated bounded cycles:

`OBJECTIVE -> BASELINE -> GAP -> SMALLEST_REVERSIBLE_DELTA -> TEST/READBACK -> RECEIPT -> LEARN -> NEXT_BOUNDED_OBJECTIVE`

The next cycle may reuse a previously authorized `F_next`, but cannot silently widen purpose, population, privacy boundary, repository authority or claim scope.

A failed/negative control is useful evidence and must be retained. Improvement means reducing demonstrated risk/uncertainty or increasing reconstructibility, not merely increasing file count or automation volume.
