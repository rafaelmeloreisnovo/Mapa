# OECG V1 continuous-improvement stop rule

Continuous improvement is cyclic, but each cycle is finite.

A cycle MUST stop and issue a receipt when any one is true:

1. the authorized objective and CTQ are satisfied within scope;
2. the next required input is external/provider-controlled and explicitly typed as TOKEN_VAZIO;
3. an ethics/privacy/dignity/child-safety gate blocks further processing;
4. an authoritative probe produces no material delta;
5. the remaining work belongs to a different producer authority and must be routed rather than copied.

A new cycle requires a human-authorized objective or a previously authorized bounded F_next. It does not arise from self-generated mission expansion.
