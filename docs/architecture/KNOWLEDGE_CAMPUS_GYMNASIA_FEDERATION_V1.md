## Gymnasium semantics

A Gymnasium is a relation-dense arena. It can join a patent-like system decomposition, a mathematical formula, a code subsystem, a parable and an evidence record without flattening them into the same epistemic type.

Every object may expose:

```text
materialization_state
characteristics
source_authority
evidence_state
privacy_class
reversibility
retrieval_tier
gaps
dependencies
downstream_effects
```

Component decomposition uses SYSTEM → SUBSYSTEM → COMPONENT → CHARACTERISTIC → RELATION → EFFECT → EVIDENCE.

Counter-rotation, reaction torque, control-moment analogies, movable-wing/fixed-wing comparisons and similar cross-domain examples can be stored as ANALOGY_TO or RELATES_TO. They do not become EVIDENCED_BY without a separate physical source/test.

## Relation classes

- structural: CONTAINS / COMPONENT_OF / CHARACTERISTIC_OF
- semantic: RELATES_TO / CORRELATES_WITH / ANALOGY_TO
- causal candidate: DERIVES_FROM / PRODUCES / REQUIRES / BLOCKS
- epistemic: EVIDENCED_BY / CONTRADICTS / SUPERSEDES
- navigational: NEXT / PREVIOUS

## Retrieval logistics

The campus consumes the existing semantic-carrier HOT/WARM/COLD/ARCHIVE policy. Temperature changes placement and refresh cadence only; it does not change truth, authorship or evidence.

Default query starts with at most three roots and depth one. Expansion happens only for missing source, contradiction, unresolved authority, missing evidence or explicit request.
